Record an opening balance when bringing an employee's existing leave balance into Bilibi. Record an adjustment to correct a balance later. Entries remain in the history; correct a mistake with another adjustment.

Describe `people.leave.entry.record`, then prepare its input with the company, employee employment ID, active leave type ID, entry type, quantity, date, source and entry key. Employee IDs are People employment IDs, never account, Person or affiliation IDs. The employee must currently work at that company. The date determines the leave year using the company's year start month.

For example, an opening quantity of `"5.25"` adds 5.25 of the leave type's unit. An adjustment of `"-0.50"` subtracts half a unit. Quantities must be exact decimal strings, non-zero, within -9999.99 to 9999.99 and no finer than hundredths. Bilibi takes the unit from the type; do not supply one. An optional note has at most 500 characters; surrounding whitespace is removed and a blank note is omitted.

Choose your own source (1–32 UTF-8 bytes) and an entry key (1–160 UTF-8 bytes). The sources `policy`, `request` and `carry_forward` belong to Leave and are refused. Keep the same source and key for retries. The company, source and key identify one entry. An identical retry returns it without adding another entry. A retry with a different employee, type, entry kind, quantity, date or normalized note is refused. A fresh entry needs a fresh key.

Use the plan tool to review the change. Show the person the returned instance label, role and address, company, employee, type, quantity, unit, date, leave year, source, key and note. The review says `created` for a new entry or `existing` for a retry. Obtain the person's consent, then commit that exact plan. Direct write calls are refused. A plan code can be used once; if the response was lost, obtain a new plan with the original source and entry key.

You need `people.leave.policies.manage` and access to the named company. Bilibi checks permission and current employment again at commit. Archived companies, archived or missing leave types, another company's employees, a closed leave year and conflicting keys are refused. An identical retry still checks current access, employment and type status; it may return an existing entry from a closed year. If reviewed facts change, review a new plan. Never invent a new key to bypass a conflict; check the original entry first.
